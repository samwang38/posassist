# 庫存與調撥第一版：士林單機試用

版本：`1.6.0-preview.4`。提供找貨、主機備貨；已取消獨立調撥清單，預設關閉。這份安裝包供單機驗證，沒有發布至全店自動更新。

## 安裝與啟用

1. 結束本機 EPB，先備份既有 `EPB/PosAssist/` 資料夾，再解壓本機試用包，執行 `安裝_PosAssist.command`。安裝器保留門市既有設定與結帳代碼；不修改原廠檔案。
2. 開啟設定，勾選「庫存與調撥（SA 單機試用）」，預設收貨倉填 `SA004`，儲存並重開 EPB。也可在既有 `config/posassist.properties` 加入或修改下列兩行；不要用範本覆蓋整份設定。

   ```properties
   enableInventory=true
   inventoryDefaultStore=SA004
   ```

3. 使用 SA 公司帳號登入。開啟 STORESUM 後，查詢條件工具列會出現「庫存工具」。登入時不彈解說或庫存視窗，也沒有常駐庫存浮動面板；點按按鈕才開啟。庫存功能不需 POSN；會員與結帳輔助仍依 POSN 狀態顯示。已啟用 preview.3 的本機升級後保留原設定，不用再次啟用。
4. 執行 `驗證_PosAssist.command`。庫存開關啟用時會額外檢查遠端查詢及權限 API；通過代表掛載 API 存在，仍需下列實機驗收。

預覽版啟動器看到本機版本含 `-preview.` 時，略過 jar 與啟動器的自動更新，不改寫原有 `autoUpdate` 偏好。安裝回正式版後會沿用原設定。要退回，可停用庫存開關並重開，或還原安裝前備份；緊急時使用原本 EPB 捷徑。

## 操作

**找貨**：從 EPB 應用程式選單開啟 STORESUM 存貨彙總，點存貨代碼放大鏡，沿用原生多關鍵字搜尋（如 `ipad air 256`）、勾選、按 OK。接著點查詢區工具列的 **「庫存工具」**；不必先執行原生庫存查詢。

每次按「庫存工具」，比較商品都以**原生目前勾選**為準，取代上一次的商品範圍，不再累積。取消勾選的商品立即移除；仍勾選的商品保留已修改需求量，新勾選商品預設 1。同型號不同代碼分開計算，最多 30 項、每項需求 1–9999。僅支援存貨代碼「等於／包括」明確選取；清空條件或包括清單為空時會清空比較。範圍、模糊、合成條件或超過上限仍拒絕帶入並保留當前比較。

「庫存比較」是一張表：**商品往下排、門市往右排，每格只有現有帳面庫存**。左側固定商品代碼、品名、型號、需求，左右捲動門市時仍看得到商品；上下捲動兩側保持對齊。長品名／門市名稱可移入滑鼠看完整提示。視窗可調整大小，沒有缺口或調後庫存欄位。

預設顯示全部足量的門市；勾選「顯示所有門市」可看不足或零庫存門市。沒有單店足量時會提示切換。門市仍按足量品項較多、調完歸零較少、調後剩餘總量較多、門市代碼排序；這是帳面庫存比較，不自動拆店。

修改需求量或移除商品會依完整快照立即重算；同步原生勾選及「更新庫存」會重新查詢。點商品列可「移除選取商品」或「清空比較」；這些動作只影響輔助比較，不改動原生勾選，下次按原生「庫存工具」仍以原生勾選為準。關閉視窗後不自動彈回，再點 STORESUM 按鈕即可開啟。

比較使用輔助工具設定的收貨店與帳號可見 SA 一般門市，**不沿用原生的倉庫、數量等篩選**。原生結果列可能隱藏零庫存，因此只讀取原生商品代碼，再重新查遠端完整庫存。

**主機備貨**：在同一庫存工具視窗切到「主機備貨」，選 Mac、iPad、iPhone 或 Apple Watch，再按比較庫存。以精確商品代碼比較收貨店與同店型 SA 一般門市，含零庫存門市，排除收貨店及特殊倉。橫向捲動可看全部欄位。「本店缺貨、其他店有貨」優先列出；比較差額為 `max(0, ceil(同店型中位數) − 本店庫存)`，不是銷售預測。按「用這項商品找貨」會將該商品加入同一比較、帶入差額並查庫存；差額為 0 時暫設需求 1，再自行修改。已選商品保留原需求量，不重複累加或覆蓋。下次從原生「庫存工具」帶入時，同樣由原生勾選取代比較範圍。

本版已移除調撥清單頁、用途／備註、複製清單與原生申請入口。選取商品只用於庫存比較，不要求另外填寫調撥資料。

勾選商品只在本次登入記憶體保留：切頁、關閉比較視窗、STORESUM 或 POSN 不清除；登出、切換登入身分或結束 EPB 後清除。

## 查詢範圍與失敗顯示

- 庫存唯一來源是遠端 `STORESUM`，公司 `01`；只納入有效、數字店碼的 SA 一般門市，店型 `1_APR`／`2_AAR`。門市對照先去重再供庫存篩選，不直接 join 庫存造成乘算。
- 商品限正常品 `CAT1_ID=1001`、主機／原廠配件／3PP `CAT3_ID=3001/3002/3003`、有效狀態；STORESUM 原生檢視表僅納入實體商品明細。排除可識別的展示、專案、非銷售品；規則集中在 `InventorySql`，主機分類集中在 `Inventory.Category`。AirPods 可找貨，但不列入主機備貨分類。
- 沿用登入環境的遠端設定、應用程式權限、門市與商品分類可見範圍，不額外要求連線帳密。比較母體是帳號可見的有效門市；畫面顯示實際比較店數。
- 一次只執行一個背景工作，最多一個待執行工作。畫面等待上限 45 秒；底層 EPB 傳輸可能稍後才結束，期間重試仍受單一工作限制，較晚回應不覆蓋新結果。
- 原生選取後，以精確商品代碼從 STORESUM 確認資料、可見範圍及單位，再整批帶入。若其中一項不支援或缺資料，新商品不部分匯入，列出代碼；已取消勾選的舊商品仍會移除，仍勾選的原有商品保留，但庫存顯示未知。可回原生取消勾選該項後重試。
- 原生搜尋可能包含展示品。例如驗證樣本 `09600039` 為 Demo、非正常銷售分類，會擋下包含它的整批帶入；不要將此提示解讀為全店缺貨。
- 庫存結果最多 30,000 個門市／商品彙總列。超量、不完整、逾時、欄位或單位異常顯示未知／需更新，不套用部分結果。只有成功完整且已確認商品身分的快照才能把缺少的門市庫存列視為零，並顯示快照時間。
- 已選商品在完整回應中完全消失時，提示重新搜尋，不把商品停用或權限變更誤認為全店零庫存。

## 士林實機驗收紀錄

開發驗證結果另見 `inventory-validation.md`。使用者已確認 preview.3 查詢正常並提供兩項 AirPods 比較截圖。下列操作變更仍需安裝 preview.4 後實機核對，離線驗證不能取代現場回歸。

| 操作 | 預期結果 |
|---|---|
| 同公司、倉庫、商品與原生 STORESUM 對照 | 庫存一致，負數保留；記錄時間與原生查詢條件 |
| 兩商品單店足量／一項不足／調完歸零 | 篩選、排序正確；格內只有現有庫存 |
| 原生取消舊項改勾新品、清空、同型號不同代碼、改數量 | 清單與原生一致；共同商品保留需求，各代碼獨立，空勾選清空 |
| 本店完全無該商品庫存列、比較店包含零庫存 | 可找到其他店有貨商品，中位數含零 |
| 暫時斷線、快速連續查詢、查詢期間改清單 | 保留勾選商品，不誤報足量、不套用舊回應 |
| POSN 開關、STORESUM 切換 | 庫存勾選商品保留，POS 輔助依 POSN 狀態變更 |
| 登入、STORESUM 重開、關閉比較後切換原生畫面 | 不自動跳出視窗，按鈕不重複；點按才顯示 |
| 調小比較視窗、30 項商品、左右／上下捲動 | 商品固定左側，門市表頭與庫存對齊 |
| 會員查詢、結帳代碼、掃碼焦點 | 原有功能正常；庫存回應不自動送焦點到 POS |
| 登出後再登入 | 不留下上一登入的商品與快照 |

試用問題請記錄版本、時間、登入公司／門市、料號、預期與實際結果、SelfTest 輸出。不要附客戶資料或帳密。
