## 1.6.0-preview.4：點按開啟、原生勾選同步與商品列比較

驗證日期：2026-09-07。本次只產出本機試用包，未替換目前安裝，也沒有發布全店更新。

| 驗證 | 結果與界線 |
|---|---|
| Java 8 建置與 `test.command` | 庫存測試 123 項、自訂會員欄位測試 7 項、preview 自動更新隔離 3 項全部通過 |
| 本機 EPB SelfTest | 以新版 jar、現有 EPB 類別及本機既有設定執行，118 項全部通過，含 TLS 交握；未修改會員設定。初次受 sandbox 網路限制的 DNS 失敗，允許唯讀連線後重跑通過 |
| Swing 示例版面 | 1180×760、850×520、主機備貨、30 商品／20 來源店及捲動後畫面，位於 `dist/inventory-qa-preview4/`；商品固定左側，門市欄頭跟隨橫向捲動，上下捲動保持列對齊 |
| 原生查詢現場證據 | 使用者確認 preview.3 查詢正常；截圖顯示 `07310978`、`07312495` 比較成功及 31 間符合篩選門市。這是上一版查詢正向驗證，不代表 preview.4 新 UI 已現場驗收 |

本版移除登入自動開啟的庫存浮動面板，STORESUM 只掛按鈕，第一次點「庫存工具」才建立查詢面板；主機備貨保留在同一視窗分頁。比較改為商品列、門市欄，只有帳面庫存數字，需求與商品資料固定左側。視窗關閉不自動彈回，POSN 原有輔助仍依 POSN 狀態掛載。

本次原生選取以取代為準：取消勾選立即移除，仍勾選的保留數量，新商品預設 1，空條件／空 IN 清空。新資料不完整時不部分加入，不復活已取消商品；快速連續 A、B 選取以最後的 B 為準。測試涵蓋第一次點按先載入門市再匯入、登入僅建立工作區不建立面板、精確取代、舊回應隔離與單值矩陣。

SelfTest 原本固定要求 gender，但既有 `vipCreateFields` 可自訂欄位。本版依預設／自訂設定分別檢查，不強迫增加 gender、不覆寫現有欄位；測試涵蓋實際四欄設定與超過六欄的合法自訂。

安裝後仍需確認：登入無自動解說／庫存視窗、STORESUM 點按與重開、原生取消勾選及空選取、視窗關閉／重開、需求編輯、POSN 會員／結帳與掃碼焦點、登出清除。此版未在登入中的 EPB 替換執行，因此不將上述回歸標為通過。

以下保留各版當時的驗證紀錄；其中 preview.3 累積商品與常駐庫存面板已由 preview.4 取代。

## 遠端資料快照

Query Kit 可見範圍當時有 33 間有效 SA 一般門市，包含 SA004。各分類的商品數是一般門市 STORESUM 中符合正常品規則的不同商品代碼數；不是有貨商品數。

| 分類 | 商品代碼數 | SA004 庫存偏低項目 |
|---|---:|---:|
| Mac | 1,212 | 28 |
| iPad | 192 | 42 |
| iPhone | 312 | 31 |
| Apple Watch | 315 | 16 |

兩商品驗證使用實際分類結果中的 `07313116`、`07313119`，精確搜尋均找到，再取得包含 33 店的完整庫存快照；SA004 當時兩項均為 0。以上為測試當下數字，營業使用須重新查詢。Query Kit 的可見範圍不代表每個店員帳號都可見相同門市；生產介面使用原生登入權限。

開發時發現直接在 STORESUM 做廣泛模糊搜尋會逾時。修正為先用商品主檔縮小候選料號，再由 STORESUM 查詢並驗證商品資格／權限。主機比較保留 STORESUM 完整範圍，移除會逐列呼叫原生計算函式的多餘 TYPE 條件；以原生檢視表的 `LINE_TYPE='S'`、正常品分類及排除規則限制商品。四類查詢實測各約 28 秒；正式面板設 45 秒顯示逾時，速度仍受遠端負載影響。

候選商品上限 1,000、搜尋結果上限 100；太廣泛（如只輸入 MacBook Air）可能要求縮小條件。庫存結果上限 30,000，超量時整次結果失敗，不套用部分結果。SQL 回傳 `COUNT(*) OVER()` 完整性筆數，傳輸列數不符同樣拒絕。

## 重跑方式

```bash
./test.command
java -Djava.awt.headless=true -cp build:build/tests com.posassist.InventoryVisualCheck dist/inventory-qa
# 僅開發環境；使用既有唯讀 Query Kit，不隨門市安裝包提供 Python：
java -cp build:build/tests com.posassist.InventoryLiveCheck /absolute/path/to/epb_query.py
./打包.command
```

上述 `java` 使用 Java 8；安裝端執行 `驗證_PosAssist.command` 做 EPB 掛載 API 檢查。`打包.command` 會重新建置並清理測試 class，先跑驗證再打包。
